# Site IA (Information Architecture)

Structure **multi-page** websites so users and crawlers can find the right page without noise.

## Triggers

site map · IA · information architecture · website structure · navigation design · URL map · multi-page site · nav model

## Principles

1. **User tasks first** — primary jobs to be done drive top nav, not org chart.
2. **Shallow when possible** — prefer fewer levels; deep trees hide content.
3. **Page types over page count** — template once (hub, detail, docs, legal).
4. **URLs are UI** — readable, stable, hierarchical only when meaningful.
5. Marketing home ≠ app shell — don’t force one nav model on both.

## Typical page types

| Type | Examples |
|------|----------|
| Marketing | Home, product, pricing, about, contact |
| Conversion | Landing, signup, demo request |
| Content | Blog index, article, resources |
| Product/docs | Docs home, guide, API ref, changelog |
| Account | Login, settings, billing |
| Legal | Privacy, terms, security |

## Workflow

1. List audiences and top tasks.
2. Draft sitemap (hierarchy or hub-and-spoke).
3. Define primary nav (≤7 items ideal), utility nav, footer nav.
4. URL map (`/pricing`, `/docs/getting-started`, …).
5. Per-template content outline (required blocks).
6. Note SEO landing candidates (`seo-page`) and conversion pages (`landing-page`).
7. Call out risks: duplicate paths, orphan pages, nav overload.

## Output

- Sitemap (tree or table)
- Nav specification (primary / utility / footer)
- URL map
- Page-type templates list
- Open IA questions

## Handoffs

- Page content & guides → Page Master
- Individual conversion pages → `landing-page`
- Visual nav components → `design-system` + `a11y-build`
- Diagram of structure → `diagram-design`

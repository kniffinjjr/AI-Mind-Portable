**Post:** https://x.com/gippp69/status/2083992907896238095

**Paper:** arXiv:2507.03724  

## Claim (post)

Agents that learn one wrong preference can replay it for 100 sessions. MemOS makes every stored memory **inspectable, editable, and removable** instead of a black-box vector dump.

Pipeline: chat → extract facts → graph-structured memory → cross-task retrieve → correct stale state → delete junk.

**Reported numbers (vendor + post):**

- OpenClaw task completion **36.63% → 50.87%** with MemOS  
- **~35.24% fewer memory tokens** (retrieve useful knowledge vs reread full history)  
- Benchmarks claimed: LoCoMo 88.83, LongMemEval 89.20, plus OmniMemEval suite  

## What MemOS actually is (from README)

A **Memory OS** for LLM agents: unified store / retrieve / manage with:

| Feature | Notes |
|---------|--------|
| Unified API | Add, retrieve, **edit**, **delete** — graph-structured, inspectable |
| Multi-modal | Text, images, tool traces, personas |
| Memory cubes | Isolate / share knowledge across users, projects, agents |
| Async scheduler | Production ingestion path |
| Feedback correction | NL feedback to fix or replace memories |
| Deploy options | Cloud API, self-host (Docker + Neo4j + Qdrant), OpenClaw/Hermes plugins (cloud or 100% local SQLite) |

Quick self-host (from post/README):

```bash
git clone https://github.com/MemTensor/MemOS.git
cd MemOS
cp docker/.env.example .env
cd docker && docker compose up
```

## Critical review (for AI Mind)

### What is strong / true-to-our-stack

1. **Inspectability = harness + eval alignment.** Our vault already rejects pure “thermometer” memory (single-file AI_Mind eval 54%). MemOS’s edit/delete story is the same control-flow idea: memory is state the human (or broker) can gate.  
2. **Graph memory, not only vectors.** Matches [[Harness-Loop-Graph-Architecture]] — topology and state schema matter; black-box RAG alone is not enough.  
3. **Memory cubes ≈ multi-tenant isolation.** Maps cleanly to Projects/, Work vs Personal brain dumps, and Review Queue (don’t mix unrestricted agent write into live knowledge).  
4. **Token savings claim is directionally right.** Selective retrieve vs stuffing full history is the same budget discipline a usage dashboard surfaces.  
5. **Plugins for OpenClaw/Hermes** show FDE-style “ship integration artifacts” (MCP/skills/memory adapters) — see [[Forward-Deployed-Engineering]].

### Skepticism / risks

1. **Benchmark marketing.** Post is hype-format; OpenClaw +35pp and “leads OmniMemEval” need independent reproduction on *your* tasks, not only vendor tasks.  
2. **Ops weight of self-host.** Full stack wants Neo4j + Qdrant + LLM/embedder keys. Local plugin (SQLite) is lighter but different fidelity.  
3. **Not a substitute for AI Mind Vault.** MemOS is runtime agent memory; the vault is human-gated durable knowledge. Complementary: MemOS for session/preference memory; vault for approved methodology and projects.  
4. **Wrong preference problem is real** — but fixing it needs **write policies + review**, not only better storage. MemOS enables correction; it does not replace Review Queue discipline.  
5. **Privacy:** Cloud path (memtensor.cn / dashboard) may be a non-starter for employer or personal-finance memory. Prefer local plugin or self-host if sensitive.

### Practical recommendation

| Priority | Action |
|----------|--------|
| **Low-cost trial** | Install **memos-local-plugin** for a single agent runtime if/when using OpenClaw or Hermes; do **not** put work PDM secrets in cloud MemOS without policy review |
| **Vault** | Keep Review Queue as the permanent gate; optionally log MemOS as an *option* under agent harness templates (persistence row) |
| **Do not** | Replace a usage dashboard or terminal host with MemOS — different layer (memory OS vs observability vs host) |
| **Eval first** | If adopting: pick one loop (e.g. job-search preferences or hardware diagnostics) and measure intervention rate + wrong-recall rate before/after |

Treat as **research candidate**, not default infrastructure, until a local pilot proves value on your agent host.
